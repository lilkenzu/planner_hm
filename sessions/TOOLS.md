# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-16 · Сессия 1 · SSH-ключ для GitHub (agent push)

- **Тип:** сервис / окружение (SSH-аутентификация)
- **Установка:** `ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_github -N "" -C "planner_hm-agent"`,
  запись в `~/.ssh/config` (алиас для `github.com` на этот ключ), `ssh-keyscan` в
  `known_hosts`, публичный ключ добавлен пользователем в GitHub → Settings → SSH keys.
- **Зачем:** пуш через HTTPS с `git ls-remote`/`git push` падал в этой изолированной
  среде — нет сохранённого токена в Keychain и нет интерактивного терминала для
  ввода логина/пароля (`fatal: could not read Username for 'https://github.com':
  Device not configured`). SSH-ключ без пароли устраняет интерактивность полностью.
- **Область:** глобально для машины пользователя (`~/.ssh`), remote репозитория
  переключён с HTTPS на SSH (`git@github.com:lilkenzu/planner_hm.git`).
- **Проверка:** `ssh -T git@github.com` → «Hi lilkenzu! You've successfully
  authenticated…»; затем `git push -u origin main` прошёл успешно, ветка `main`
  появилась в удалённом репозитории.
- **Заметка о компромиссе:** ключ сгенерирован без пароля (`-N ""`) специально,
  чтобы агент мог пушить без интерактивного ввода. Это снижает защиту ключа при
  краже файла с диска — приемлемо для учебного репозитория, но не для боевого
  проекта с секретами.
