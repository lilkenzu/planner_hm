# Спецификация

## Что делаем

Веб-страница для поиска удобного окна встречи для распределённой команды: организатор
добавляет участников с их часовыми поясами и рабочими графиками, инструмент строит
недельную сетку доступности и показывает, когда и насколько команде удобно созвониться.

## Для кого и зачем

Для человека, который организует встречу с командой, работающей из разных стран
(тимлид, координатор, любой сотрудник, кому нужно подобрать время для звонка).
Решает задачу ручного пересчёта часовых поясов в уме и попыток удержать в голове,
у кого какой рабочий график.

## Сценарии

1. **Основной.** Организатор добавляет участников по одному: имя, город (часовой пояс
   определяется по нему), диапазон рабочих часов в его локальном времени, рабочие дни
   недели. После добавления первого участника сразу видна сетка на ближайшие 7
   календарных дней (реальные даты, а не абстрактная неделя) с шагом 30 минут. Каждая
   строка сетки — отдельный участник, время показано в его собственном локальном
   поясе. Заливка ячейки отражает долю участников, доступных в этот момент.
2. Добавление ещё одного участника — сетка пересчитывается сразу, без перезагрузки.
3. Редактирование участника (город, часы, дни) — сетка пересчитывается.
4. Удаление участника — сетка пересчитывается; при удалении последнего — возврат
   в пустое состояние.
5. Клик по ячейке с неполной доступностью — список участников, которые в этот момент
   недоступны, и причина: нерабочий день / до начала рабочего дня (на сколько) / после
   окончания рабочего дня (на сколько).
6. Если ни один слот за неделю не набрал 100% участников — над сеткой появляется баннер
   с лучшим найденным слотом (день, время, сколько участников доступно из скольких),
   сама ячейка этого слота подсвечена в сетке. Выбор слота всегда остаётся за человеком —
   инструмент только подсказывает, куда смотреть в первую очередь.
7. Ввод несуществующего/нераспознанного города при добавлении участника — участник
   не добавляется, ошибка показывается у поля, остальная форма не ломается.

## Состояния

- **Пусто** (первый заход): участников нет — видна только форма добавления, сетки нет.
- **Есть данные**: 1+ участников — сетка на 7 дней с заливкой по проценту доступности,
  клик по ячейке раскрывает причину недоступности.
- **Нет полного совпадения**: ни один слот недели не набрал 100% участников — баннер
  с лучшим найденным слотом над обычной сеткой, соответствующая ячейка подсвечена.
- **Ошибка ввода**: город не распознан — сообщение у поля формы, участник не добавлен.
- **Возврат к пустому**: удалены все участники — интерфейс снова в состоянии «пусто».

## Чего точно не делаем

- Не отправляем приглашения и не интегрируемся с календарями (Google Calendar,
  Outlook и т.п.) — только расчёт и отображение.
- Не сохраняем данные между визитами: ни `localStorage`, ни сервер. Каждый заход —
  с чистого листа.
- Нет регистрации/авторизации, нет многопользовательского доступа в реальном времени.
- Считаем только разовый срез на ближайшие 7 календарных дней — без повторяющихся
  серий встреч и без произвольного выбора диапазона дат.
- Не бронируем и не выбираем финальный слот за пользователя — при неполном совпадении
  только подсказываем лучший вариант, решение остаётся за человеком.
- Часовой пояс — только из стандартного списка IANA, который знает браузер
  (`Intl.supportedValuesOf('timeZone')`); произвольные UTC-смещения вручную не вводятся.
- Не нативное мобильное приложение — веб-страница.
- Никаких сторонних библиотек дат/расчётов и никаких сетевых запросов — только
  встроенные `Intl`/`Date` браузера.

## Допущения

- **Шаг сетки — 30 минут.** Баланс точности и объёма сетки; учитывает нечётные сдвиги
  вроде +5:45 у Катманду, чего не даёт часовой шаг.
- **Диапазон — ближайшие 7 календарных дней от сегодняшней даты**, а не абстрактная
  неделя без привязки к датам. Это единственный способ корректно показать переход
  на летнее/зимнее время, если он попадает в этот период (обсуждали отдельно, выбран
  вариант с реальными датами).
- **Минимум участников для показа сетки — 1.** С одним участником сетка просто
  показывает его собственные рабочие часы, это не мешает логике и полезно как
  промежуточный шаг перед добавлением остальных.
- **Порог состояния «нет полного совпадения» — отсутствие хотя бы одного слота на
  100%.** Более мягкий порог (например, «максимум ниже 50%») не выбран — так проще
  и предсказуемее объяснить пользователю.
- **Часовой пояс участника вводится выбором города/региона из списка IANA-зон**,
  а не ручным вводом смещения — меньше ошибок ввода, смещение вычисляется браузером
  автоматически и с учётом текущих правил перехода на летнее время.
- **Формат времени — 24-часовой.** Не обсуждали отдельно, но это стандартный выбор
  для инструмента с международной аудиторией — избегает путаницы AM/PM между поясами.
- **Округление процента доступности — до ближайшего целого числа.** Дробные
  проценты (33.33% и т.п.) не показываем — округляем стандартно (`Math.round`).
- **Границы рабочего часа — полуоткрытый интервал [начало, конец).** Для рабочих
  часов 09:00–18:00: слот 09:00–09:30 входит в рабочее время (начало
  включительно), слот 17:30–18:00 тоже входит (последний перед концом), а слот
  18:00–18:30 уже не входит (конец не включён). Подтверждено на этом наборе
  тестовых слотов.

## Открытые вопросы

Вопросы, заданные в процессе спецификации, и ответы:

1. Кто пользователь и какой сценарий? → Команда с сотрудниками в разных странах,
   координатор ищет удобное время для встречи.
2. Верен ли сценарий «участники со своими поясами → показать удобное время»? → Да.
3. Рабочие часы — общий дефолт или ввод на участника? → Вводится индивидуально,
   с учётом места жительства каждого.
4. Рабочая неделя — общий дефолт или своя у каждого участника? → Своя у каждого.
5. Строгое пересечение рабочих часов или допускаем частичное? → Частичное пересечение;
   вместо пометки «неидеально» — по клику показывается конкретная причина.
6. На какой диапазон ищем окно? → На ближайшую неделю.
7. Формат результата? → Визуальная сетка.
8. Как задаётся часовой пояс участника? → Вводом города.
9. Нужна интеграция с календарём / отправка приглашений? → Нет.
10. Нужно сохранение состояния между визитами? → Нет.
11. Стек — одна HTML-страница без сборки, часовые пояса через `Intl`/`Date`, без
    внешних библиотек и без сети? → Да.
12. Конкретные календарные дни или абстрактная неделя (обсуждены плюсы/минусы обоих
    подходов, включая влияние на корректность перехода на летнее время)? → Конкретные
    календарные дни (следующие 7 дней от сегодня).
13. Что показываем по клику на слот с частичной доступностью? → Кто недоступен и
    почему (нерабочий день / до начала / после окончания рабочего дня, с указанием
    разницы).
14. Что показываем, если пересечений нет вообще ни в одном слоте? → Сетка всё равно
    рисуется (не скрывается за сообщением об ошибке).
15. В чьём часовом поясе показывается сетка? → У каждого участника — в его
    собственном локальном времени (строка на участника).
16. Можно ли редактировать/удалять участников, есть ли лимит по количеству? → Можно
    добавлять/редактировать/удалять; лимита нет.
17. Формат рабочих часов участника? → Диапазон часов в локальном времени + набор
    рабочих дней недели.
18. Шаг сетки (детализация)? → 30 минут.
19. Минимум участников, необходимый для показа сетки? → 1.
20. Подтверждение набора нецелей и состояний экрана? → Подтверждено, плюс добавлено
    отдельное состояние «нет полного совпадения».
21. Порог для состояния «нет полного совпадения»? → Отсутствие хотя бы одного слота
    на 100% (не мягкий порог вроде «максимум < 50%»).
22. Как показывать это состояние? → Баннер с лучшим найденным слотом над обычной
    сеткой, сама ячейка подсвечена.
23. Режим разрешений на сессию (для журнала)? → Ручной — подтверждение на каждое
    изменение файлов и каждую команду.

## Критерии приёмки

- [x] Участника можно добавить через форму: имя, город (автодополнение/выбор из
      списка IANA-таймзон), диапазон рабочих часов, рабочие дни — без перезагрузки
      страницы.
- [x] После добавления первого участника сетка на 7 календарных дней (с реальными
      датами) отображается без ошибок в консоли браузера.
- [x] Добавление, редактирование и удаление участника пересчитывают сетку сразу.
- [x] Ячейка сетки корректно отражает долю участников, доступных в этот момент,
      с учётом локальных рабочих часов и рабочих дней каждого.
- [x] Клик по ячейке с частичной доступностью показывает список недоступных
      участников и причину недоступности с указанием разницы во времени.
- [x] Тестовый кейс: участники в Москве и Лондоне, диапазон недели захватывает
      последнее воскресенье марта — сетка отражает изменение разницы часовых поясов
      в течение недели (проверка перехода на летнее время). Проверено через реальное
      приложение на неделе 24–30 марта 2026: окно полного совпадения сдвинулось
      с 09:00–15:00 UTC (27 марта, до перехода) на 08:00–15:00 UTC (30 марта, после) —
      см. `sessions/session-1.md`, шаг 7.
- [x] Тестовый кейс: участник в часовом поясе Катманду (UTC+5:45) — сетка корректно
      учитывает нечётный 45-минутный сдвиг. Проверено через реальное приложение —
      ячейки Катманду показывают :15/:45, а не :00/:30, как у остальных поясов.
- [x] Если ни один слот недели не набрал 100% участников — показан баннер с лучшим
      найденным слотом (день, время, X из N), соответствующая ячейка подсвечена.
- [x] Ввод нераспознанного города — участник не добавляется, у поля показана ошибка,
      остальная форма остаётся рабочей.
- [x] Удаление последнего участника возвращает интерфейс в пустое состояние.
- [x] На вкладке Network браузера нет ни одного сетевого запроса от страницы; в коде
      нет подключений сторонних npm-пакетов или CDN-библиотек. Проверено: после
      загрузки страницы добавление/редактирование/удаление участника и клик по
      сетке не создают новых запросов (кроме одного `data:`-URI иконки нативного
      `<input type="time">`, который не обращается к сети); `grep` не находит
      `import`/`require`/CDN/`package.json`/сборщиков/`fetch`/`XHR`/`WebSocket`.
- [x] Функция расчёта доступности покрыта автотестом
      (`tests/availability.test.js`): получасовой/45-минутный сдвиг пояса,
      переход через полночь, обе границы рабочего часа, случай с 1 участником —
      тест проходит, вывод показан.

## План реализации

Пошаговый план: одна задача — один вызов агента, приёмка по критерию «готово, когда…»
перед переходом к следующему шагу.

1. **Форма и список участников.** Добавление/редактирование/удаление участника
   (имя, город, часы, дни), без логики пересечений.
   *Готово, когда:* участника можно добавить/отредактировать/удалить через форму,
   список виден на странице, нераспознанный город даёт ошибку у поля.
2. **Локальное время участника через `Intl`/`Date`.** Конвертация произвольного
   UTC-момента в локальное время и день недели участника, без библиотек.
   *Готово, когда:* для тестового участника в поясе Катманду на заданный UTC-момент
   верно выводятся локальные час, минута и день недели (45-минутный сдвиг учтён).
3. **Сетка на 7 дней с шагом 30 минут и расчёт доступности.** Для каждого слота —
   доля участников, доступных по их локальным рабочим часам/дням, округлённая
   до целого процента.
   *Готово, когда:* минимум 3 тестовых участника — из разных часовых поясов,
   с разными рабочими неделями; один из них в поясе с получасовым/45-минутным
   сдвигом (например, Катманду); один подобран так, что его локальная полночь
   попадает в проверяемый диапазон дат. Правило границ рабочего часа проверено
   на конкретных слотах: для рабочих часов 09:00–18:00 слот 09:00–09:30
   доступен, слот 17:30–18:00 доступен, слот 18:00–18:30 недоступен. Отдельно
   проверен вырожденный случай — сетка с 1 участником (100% в его рабочие часы,
   0% вне них). Проверка выполнена автотестом (`tests/availability.test.js`,
   чистая функция без DOM и без библиотек) и вручную — на слотах, разбирающих
   все перечисленные случаи, с показанным выводом.
4. **Отображение сетки по участникам и детали слота.** Строка на участника в его
   локальном времени, заливка по проценту, клик — причина недоступности.
   *Готово, когда:* клик по частично доступному слоту показывает список недоступных
   участников с причиной и разницей во времени.
5. **Состояние «нет полного совпадения».** Баннер с лучшим слотом + подсветка ячейки,
   если ни один слот не набрал 100%.
   *Готово, когда:* тестовый набор участников без общего 100%-слота показывает баннер
   с верным лучшим слотом (день, время, X из N) и подсвеченной ячейкой.
6. **Пустое состояние и ошибки ввода.** Стартовый экран без участников; обработка
   нераспознанного города; возврат к пустому экрану при удалении всех участников.
   *Готово, когда:* с нуля виден только пустой экран с формой; ввод несуществующего
   города не добавляет участника и показывает ошибку; удаление последнего участника
   возвращает к пустому состоянию.
7. **Проверка пограничных случаев.** Москва/Лондон на переходе летнего времени,
   Катманду +5:45 — ручной прогон с реальными датами, вывод зафиксирован в `sessions/`.
   *Готово, когда:* оба сценария прогнаны вручную, результат задокументирован,
   расхождений с ожиданием нет (либо расхождения зафиксированы и объяснены).
8. **Финальная проверка.** Отсутствие сетевых запросов и сторонних зависимостей,
   README, журнал сессии.
   *Готово, когда:* вкладка Network пуста при работе со страницей, в коде нет
   npm/CDN-подключений, README позволяет открыть файл и повторить все сценарии.
